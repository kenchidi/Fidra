Two ways to get a reference

Every answer says how strong it is.

Fidra picks the path from the referee's bank. Each result carries an assurance level, so you can see whether the referee said it or their bank confirmed it.

self_attested

Path A: referee link

The referee receives a secure link, confirms whether the account is in good standing, and says how long they have held it.

  • Works with any referee bank, with no integration needed
  • The answer is the referee's own statement
  • Links expire, and every step is recorded
bank_confirmedPilot · available with connected banks

Path B: bank-confirmed

When the referee's bank is on the Fidra network, the bank confirms the account from its own inbox or API, and the referee agrees to the check.

  • The bank confirms the account exists and is active
  • A missing account stops the request early
  • The result is marked as confirmed by the bank

    Built for audit
    
 
    A clear record of every reference.
    
 
    Fidra is infrastructure. It should be quiet, predictable and easy to inspect.
    
 
    
  
    Consent on record
    Every request records whether the customer consented, and when.
    
  
    Full status history
    Each change is stored with who made it, when, and an optional note.
    
  
    Links that expire
    Referee links stop working after a set period, so old requests cannot be reused.
    
  
    Keys shown once
    API keys are stored hashed and displayed only when an institution is created.
